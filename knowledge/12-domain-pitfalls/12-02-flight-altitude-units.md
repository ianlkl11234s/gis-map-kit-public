## 原則
高度單位只在資料落地時無條件轉換一次，前端不做任何單位猜測；預處理對高度與時間欄加值域檢查，超出範圍直接報錯。

## 症狀
- 大範圍（全國、全球）視角下 3D 航跡貼地壓扁，放大到單一機場又看似正常。
- 同一條軌跡中段高度突然掉一截再跳回去。
- 地圖上的誤導：飛行高度被畫成約 1/3（或更低），看起來像低空飛越城市；不同縮放層級的同一班機高度不一致，讓人以為是資料本身有爬升異常。

## 原因
1. ADS-B／商業航跡 API 的高度通常是英呎（多為 25 ft 量化），但抓取程式只轉「看起來像英呎」的值（例如 `alt > 1000 ? alt*0.3048 : alt`），低空點保留英呎，同一條 path 混用兩種單位。
2. 為了遮掩上面的錯，前端再寫「相鄰點跳太多就轉換」的 heuristic。它對取樣密度有隱含假設：點很稀的 LOD 路徑，正常爬升相鄰差就很大，於是被再轉一次，變成雙重 ×0.3048。
3. 另一支補抓腳本自己寫輸出格式，欄位對錯（把地速寫進時間戳欄），而且沒轉單位。

## 解法
1. 單位轉換在資料落地時無條件做一次，不要有條件判斷；前端不猜單位。
2. 同一批檔案由多支腳本寫入時，共用同一份序列化程式碼，或至少共用格式測試。
3. 預處理加範圍警示：高度超過約 16,000 m、時間戳欄小於 1e9 之類的值直接報錯。
4. 已腐蝕的資料若轉換是確定性的，可用量化特性（例如原始高度恆為 25 ft 倍數）精確反解；這類遷移通常不冪等，要加 marker 檔防止重跑。

## 怎麼偵測
- 通用：同一班機在不同縮放或不同 LOD 下的最大高度應相同；巡航高度應落在約 9,000–12,500 m。畫一張「各班最大高度」直方圖，出現約 3,000–4,000 m 的第二個峰就是英呎被當公尺。
- 通用：抽一班檢查 path 每一欄的值域：時間欄應大於 1e9，高度欄應小於約 16,000（m）。
- 搜尋：`rg -n '0\.3048|3\.28084|feet|ft\b'`，確認只出現在落地轉換一處；出現在前端或帶條件式（`>\s*1000\s*\?`）就要檢查。
- 搜尋：`rg -n -i 'fixAlt|altitudeUnit|isFeet|looksLikeFeet'`（前端單位猜測 heuristic）。

## 出處
- ICAO／ADS-B 慣例：氣壓高度以英呎回報。
- 實例：[mini-taiwan-pulse 歷史航跡盤點](https://github.com/ianlkl11234s/mini-taiwan-pulse/blob/af703e85417277c83391cfe446f7771c209ad2b8/docs/features/historical-flight-trails/inventory-2026-09-18.md)：使用來源航跡時不得再次把高度由英呎轉公尺。
