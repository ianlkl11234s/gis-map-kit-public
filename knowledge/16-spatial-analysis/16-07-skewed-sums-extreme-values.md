## 原則
對金額、面積、長度這類長尾數值做加總、平均或空間統計前，先列前幾大值與它們占總和的比例；有單一值主宰時，總和要搭配中位數或件數，轉換（取對數、排名、排除）先講明再用，並在回答點名極端值。

## 症狀
- 「哪一區資本額最高」的第一名，其實只是一家超大公司登記在那裡；拿掉它，排名完全不同。
- 兩個月份的總和差了好幾成，看起來像整體成長，其實是少數幾筆極端值變動。
- 格網總和圖只有一兩格是深色，其他全淡，看不出分布。
- 熱點或群聚結果被單一單元拉著走（[16-01](16-01-hotspot-clustering-methods.md) 解法 9）。

## 原因
1. 長尾分布下，總和與平均由最大的幾筆決定，不代表多數單元的情況。
2. 極端值常混著兩種東西：真實的大值（大型企業）與輸入錯誤（單位填錯、多打幾個 0）；不分開就一起進統計。
3. 預聚合表的中位數、平均這類欄位不能再加總或平均，硬算就是錯數。

## 解法
1. **先看分布**：每個數值欄列出前 3–5 大、最大值占總和的比例、中位數與 p99；單一值占總和的比例明顯偏高（建議起點：超過一成，可依資料調整）就視為「被主宰」。
2. **分辨錯值與真值**：明顯超出物理或制度範圍的（例：動物體長幾百公尺）當資料錯誤，排除並列出筆數；合理範圍內的大值保留。
3. **總和不單獨報**：排名或地圖同時給件數、中位數；格網或行政區上色可改用中位數或對數分級（分級法見 [05-09](../05-color/05-09-fixed-breaks-across-time.md)）。
4. **轉換是口徑決定**：取對數、改用排名、排除前 N 名都會讓數字和別人的對不上，先講明或問過再換，不要默默換掉；換了就在回答寫出原始值與轉換後的差異（敏感度）。
5. **不可加總的欄位不加總**：中位數、平均、比例要從明細重算，不能把各格的值相加或再平均。
6. **未知不是 0**：數值欄的 null 是未提供，加總前排除並寫出排除幾筆；總和為 0 但中位數為空的單元，是「全部未知」，不是 0（[06-06](../06-data-formats/06-06-zero-null-stale-data-contract.md)）。

## 怎麼偵測
- 通用：排名第一的單元件數很少；兩期總和大幅變動但件數幾乎不變；上色圖只有極少數深色格。
- SQL：`SELECT v FROM t ORDER BY v DESC NULLS LAST LIMIT 5`，再算 `max(v) / sum(v)`；`percentile_cont(0.5)`、`percentile_cont(0.99)` 對照平均。
- SQL：對預聚合表的中位數或平均欄做 `SUM(`、`AVG(` 就是錯（欄名常含 `median|avg|mean|ratio`）。
- 搜尋：排名、熱點計算直接用 `SUM\(` 的總和欄，沒有搭配 `count|median`（適用 stack：any）。

## 出處
- 一般統計建議：長尾資料以中位數與分位數描述，轉換前做敏感度比較。
