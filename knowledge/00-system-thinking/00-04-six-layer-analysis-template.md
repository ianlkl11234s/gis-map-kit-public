## 原則
需要把現象拆成完整分析時，用六層模板組織探索並讓每層對應實際資料或標為缺口；不要把它稱為官方標準，也不要停在只呈現現況點位。

## 症狀
地圖只回答「哪裡淹水」，或把潛在淹水圖、感測器點、人口、道路各自成圖，沒有一條從條件到影響到決策的主線。也可能把某個教學模板誤稱為官方標準。

## 原因
缺少把「由現象建構完整分析」排成層次的骨架。

重要免責：這是依成熟理論整理的教學框架，參考 UNDRR 的 hazard／exposure／vulnerability／capacity 概念，並另加系統狀態、連鎖影響和介入；它不是 UNDRR 官方六層，不得標榜成官方六階段。

## 解法
六層，加上一條從介入回到前段的回饋：

| 層 | 內容 | 淹水例 |
|---|---|---|
| 1 Baseline / Susceptibility | 基線與易受影響條件 | 地形、低窪、不透水面、排水設施與容量、淹水潛勢 |
| 2 Trigger / Hazard | 觸發與致災因子 | 降雨強度、歷時、河川水位、潮汐 |
| 3 System Response / State | 系統當下狀態 | 積水範圍、深度、持續時間、IoT 感測器 |
| 4 Exposure / Vulnerability | 暴露與脆弱性 | 人口、醫院、學校、道路、不同承受能力 |
| 5 Impact / Cascading Effect | 影響與連鎖 | 道路受阻、改道、急救可達性下降 |
| 6 Intervention / Scenario | 介入與情境 | 改善排水瓶頸、滯洪、路網應變、資源優先順序 |
| 回饋 | 介入改變前段條件 | 改善排水容量回到第 1 層 |

使用注意：
- 淹水潛勢是模型或情境條件下的結果表徵，不是永遠固定、獨立的物理原因。
- 「哪裡淹水」只是第 3 層；系統觀點要問「哪裡的淹水讓更多人的交通、醫療或服務受影響」。改善點不一定是最深的淹水點。
- 可套用到其他議題，換掉各層內容即可：空污（排放與氣象基線→污染事件→濃度狀態→暴露人口→健康與活動影響→減排與預警）、水源（集水區與污染源→降雨與排放→水質狀態→取水與用水→供水中斷→保護措施）、交通擁擠（路網容量→事件與尖峰→擁擠狀態→受影響旅次→連鎖延誤→號誌或管制）。層數與命名可調，但每層都要能指到實際資料或標為缺口。
- 正式決策需要更嚴謹的模型、風險評估與驗證；此模板只組織探索。

## 怎麼偵測
檢查對象：分析報告、圖台章節結構、system map JSON 的 layer 欄位。
- 通用：論述停在第 3 層（只呈現現況點位）；或跳過第 4–5 層直接建議介入；或把「六層」寫成官方規範。
- 搜尋（文字）：`UNDRR.{0,10}(六|6)\s*層|官方.{0,6}六`（誤標官方）；報告缺 `暴露|脆弱|影響` 章節。
- 搜尋（JSON）：節點的分層欄位（若有）只出現 1–3 層。

## 出處
- UNDRR 術語頁：Disaster Risk、Disaster Risk Assessment、Exposure（概念來源，非六層來源）。
- Meadows (2008) Thinking in Systems（回饋）。
- 六層結構是整理而成的教學框架，不是外部標準。
