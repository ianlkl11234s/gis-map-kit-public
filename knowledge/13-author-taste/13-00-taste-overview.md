這是作者的設計偏好，不是業界規範；你可以不同，但要說得出理由，偏離時在 README 或 PR 寫一句。

## 原則
新專案先照下表的預設開工；要偏離時，在 README 或 PR 寫一句理由。本表自成一頁，不必再讀其他卡就能套用。

## 症狀
- 新專案每次都重新決定 SDK、底圖、字型、圓角、動態預設，每個作品長得不一樣。
- 被問「為什麼預設是這樣」，答不出理由。

## 原因
偏好沒有寫下來。本卡把偏好與理由放同一頁；每項都是「預設」，有理由就可以換。

## 解法
| 面向 | 預設 | 一句理由 | 什麼情況可以換 |
|---|---|---|---|
| SDK | MapLibre，免帳號；需要 Mapbox 專屬功能時才申請 token | 無 key、無 map load 計費壓力，可搭自架或無 key 底圖 | 需要 Mapbox 專屬樣式或功能 |
| 底圖 | 深色：免 key 用 OpenFreeMap dark（與本工具包預設相同）；自己調樣式時壓成接近黑的單色，道路與面只留低對比骨架 | 底圖退後，資料浮上來 | 要看地表實況才用衛星；亮教室、列印、白天閱讀改淺色（OpenFreeMap positron） |
| 色彩 | 近黑底＋單一強調色；類別色不用紅（紅留給警示）；發光只給「進行中」（即時、移動中、被選取），用 additive blending | 顏色與光都要有語意，到處發光就看不出什麼是即時的 | — |
| UI | 系統字、不載 web font、圓角 ≤8、資訊密度適中、顏色字級圓角取 design token | 少一個決策，也少一個字型載入 | 展示字、膠囊形按鈕視為例外並寫理由，不當範本 |
| 動態 | 動態代表資料：平滑靠資料插值，不靠 CSS／GL transition；時間軸預設不播放；尊重 prefers-reduced-motion | 裝飾性動態讓人誤以為資料在動 | — |
| 鏡頭與立體 | 總覽俯視 pitch 0、bearing 0；進入場景（機場、車站、地形）才傾斜；立體預設關、每層可開 | 傾斜會讓面積與位置比較失真，立體要對應資料量 | 高度或體積對應資料量時；移動物件這類必須立體的預設就開 |
| 尺度與密度 | 點徑固定三階；全國尺度密集點遠看熱區、近看單點 | 密度先靠透明度與熱區 | 見 [14-00](../14-scale-density/14-00-scale-density-decision-table.md) |

**反面清單（一律不做；命中時要求補一句理由，不是一律判錯）**
- 字與形：載 web font 或引用沒載入的字族；圓角 > 8；元件內寫死 hex、字級、圓角；英文大寫 eyebrow（「LEGEND」），中文標題要在前。
- 動態：時間軸或動畫預設自動播放；用 transition 冒充平滑；為動畫而動畫、無限循環明暗閃動；靜態資料加光暈；為了 3D 而 3D。
- 誠實：缺值顯示成 0（要顯示「未涵蓋」或無資料色）；假進度條、開站畫面放假即時數字；沒有功能的占位按鈕；圖例憑空發明分類。
- 底圖與密度：沒有地表實況需求卻預設衛星底圖；低縮放爆點、一次塞滿整條路網（設 minzoom 或聚合）。

## 怎麼偵測
給 gis-review：命中不等於錯，要求補一句偏離理由。
- 通用：專案 README 或設計文件有沒有寫偏離預設的理由。
- 搜尋：`fonts.googleapis|@font-face`（web font）、`border-radius:\s*(9|[1-9][0-9]+)px`（圓角）、`playing:\s*true|autoplay\s*[:=]\s*true`（自動播放）、`\?\? 0|\|\| 0`（缺值當 0）、`uppercase`（英文大寫標題）。適用 stack：any。

## 出處
- 作者個人偏好整理，非業界標準。
