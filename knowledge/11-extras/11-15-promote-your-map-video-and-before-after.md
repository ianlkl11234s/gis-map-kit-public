## 原則
被搜尋到（SEO，見 [11-01](11-01-spa-empty-html-seo-prerender.md)～[11-03](11-03-llms-txt-and-ai-crawler-policy.md)）和被轉貼（影片、對比動畫、分享預覽圖）是兩條獨立的管道，兩條都要做。轉貼素材一律用正式站的真實畫面錄製，數字可溯源、日期不捏造。

## 症狀
- 網站做好了但沒人知道；社群貼文只有連結，或一張靜態截圖。
- 影片看了頭暈（橫推、模糊、頻閃、鏡頭忽左忽右）。
- 介面改版的前後對比看不出改了哪裡。
- 影片裡的數字被讀者指出對不上，或日期與資料不符。

## 原因
- 搜尋引擎只處理被搜尋的人；社群轉貼靠的是一眼看懂的動態畫面與連結預覽，兩者素材不同。
- 用 HTML 重刻的模擬畫面與正式站有落差，讀者一點進站就發現不一樣。
- 淡入切換看不出兩邊的對應位置；轉場位移大會造成暈眩。
- 影片的數字沒有台帳，事後無法回頭查。

## 解法
1. **分享預覽**：社群貼連結時顯示的 og:image 與標題，SPA 地圖站要靠預先產生的靜態 HTML 才有，做法見 [11-01](11-01-spa-empty-html-seo-prerender.md)、[11-04](11-04-share-camera-og-image-saved-scene.md)，這裡不重複。
2. **錄製用的拍攝模式**：用網址參數直接開指定圖層與鏡頭，並隱藏面板（見 [11-04](11-04-share-camera-og-image-saved-scene.md) 分享網址、[11-06](11-06-canvas-capture-export-print.md) 截圖匯出）。選資料最豐富的時段拍（例如平日早上通勤），在正式站錄。
3. **回顧／宣傳影片的內容**：主軸講「看得到什麼」（圖層、資料），不放 commit 數與開發過程。用時間軸式敘事：寧靜開場 → 逐站加速 → 高潮 → 進階 → 一句話收尾；主題用問句引入；開場要快速鋪到「很多圖層」。一氣呵成，不要簡報翻頁感。先出 16:9，再改直式。
4. **防暈**：畫面主體穩定，前進感交給 HUD 或時間軸；轉場用光縫 wipe，位移 ≤4%；不橫推、不模糊、不頻閃；鏡頭用程式控制且方向一致（見 [04-12](../04-effects-catalog/04-12-camera-motion.md)）。配樂連續演進；響度約 -15 LUFS、true peak ≤ -1 dBTP（這是作者偏好值，平台規格以其當期說明為準）。
5. **數字與內容安全**：影片裡的數字口徑一致，且在資料台帳有出處（見 [11-13](11-13-scrollytelling-story-and-number-ledger.md)）；日期以資料實際時間為準，不捏造。新聞類排除治安、事故、點名個人；個資不入鏡。
6. **前後對比動畫**（介面改版前後）：
   - 分隔線從改版前單程掃到改版後，不掃回，不用淡入切換。
   - 每段約 2.5 秒（前 1.2 秒、掃 0.8 秒、後 0.5 秒、轉場 0.25 秒）；更短太趕，更長拖。
   - 第一格就要有畫面與標題，不從黑畫面淡入。
   - 同類小元件（圖例、控制項）合成一段交錯堆疊，略重疊但不蓋到內容，用同一縮放比例讓字一樣大。
   - 能模擬實際操作就模擬（游標滑入、點擊漣漪、真實展開過渡）。
   - 用真實畫面以 2 倍解析度重拍，不用 HTML 重刻介面；動效用 Web Animations API 暫停後逐格截圖，再合成影片。
   - 改版前畫面用舊版 commit 重建出來拍，不要憑記憶重畫。
   - 每次修改另存新版本，不覆蓋舊的。

可以調整的情況：沒有前後差異可比時，不必做對比動畫；只做單一貼文時，一張乾淨的真實截圖加一句話也可以，但仍遵守真實畫面與數字溯源。

## 怎麼偵測
- 通用：影片素材是用 HTML 重刻的模擬畫面，而不是正式站真實錄製。
- 通用：轉場用橫推、模糊或淡入；鏡頭方向不一致；畫面有頻閃。
- 通用：影片裡的數字沒有對應的資料出處，或日期對不上資料時間。
- 通用：畫面出現個人資訊，或事故、治安新聞。
- 通用：對比動畫從黑畫面淡入、淡入切換兩邊，或「改版前」是憑記憶重畫而非舊版實拍。
- 通用：貼連結到社群沒有預覽圖（見 [11-01](11-01-spa-empty-html-seo-prerender.md)、[11-04](11-04-share-camera-og-image-saved-scene.md)）。
