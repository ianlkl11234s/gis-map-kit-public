## 原則
所有非同步載入都要註冊到共用的載入狀態登記並顯示開始、成功、失敗三態；失敗、無資料、過期要分開呈現，資料時間要看得見，缺值不補 0。

## 症狀
- 資料載入時畫面沒反應，使用者以為壞了；或載入提示一閃即逝。
- 載入失敗被顯示成「沒有資料」或空白。
- 資料更新程式已經停了好幾天，畫面還是顯示正常；缺值被補成 0。
- 時間軸播到「未來」，沒有資料卻看起來有。

## 原因
載入、失敗、無資料、過期共用同一個「空」狀態；資料時間沒有被當成一等公民。

## 解法
1. **所有非同步載入都註冊到一個載入註冊表**，禁止靜默地 `fetch().then()`；UI 單一出口顯示，開始、成功、失敗三態都要可見。切換時間或日期會重抓資料的圖層最需要。原型版：一個 `loadingCount` 狀態加右上角「載入中…」即可。用測試守住這條規則見 [07-13](../07-performance/07-13-loading-state-and-lint-guard.md)。
2. **載入狀態條節奏**（可調整）：出現前延遲約 150ms（這段內完成的不顯示）、「載入中」最短停留約 600ms、全部結束後合併等待約 300ms、「已載入」停留約 2 秒後淡出、失敗停留約 4 秒；換任務只換文字不重跑動畫；播放中的時間軸只顯示「載入中」。支援 `prefers-reduced-motion`。
   - 錯誤訊息要寫給使用者看（例：「資料暫時載不到，請重新整理」），不要叫使用者去跑腳本或看 console；錯誤框要能關閉，資料之後載入成功就自動清掉。
3. **失敗的判定**：Promise reject 或後端回傳 `{ error }` 都算失敗；逾時保底不算失敗。顯示「載入失敗・名稱」並提供重試；不得改成「沒有資料」，也不要只 `console.warn`（見 [06-10](../06-data-formats/06-10-loader-column-mismatch-silent-blank.md)）。
4. **四種空/異常要分開**（資料層定義見 [06-06](../06-data-formats/06-06-zero-null-stale-data-contract.md)，畫法見 [05-04](../05-color/05-04-null-is-not-zero-color.md)）：各有各的文字，不合成為 0、「正常」或預設座標。
5. **資料年齡判定**以「來源預期更新週期」為單位，而非固定秒數：stream 型（> 2 個週期延遲、> 6 個週期過期、> 7 天停更）、日／週批次型（> N 天過期）、盤中型（收盤只顯示中性標籤，但長期無新資料仍轉過期）、事件型（地震、落雷等不判過期，因為沒事件本來就沒有新列）。多狀態同時成立時取最嚴重者。
6. **資料時間要看得見**：popup 與面板顯示「更新於／抓取於」；時間軸顯示目前時間；超過資料範圍的游標顯示「尚無資料」，不播到未來（回放停在視窗結尾與現在之中較早者）。模擬或估計結果在圖層名加「推估」；只能給範圍的數字寫「A～B」兩端都寫。時間顯示一律用同一個固定時區，不用使用者本機或 UTC。

## 怎麼偵測
- 通用：把網路切到 offline 或讓 API 回 500，看畫面有沒有失敗提示；讓收集器停一天，看畫面有沒有警示；把時間軸拖到未來。
- 搜尋：`\.then\(` 且無錯誤處理的資料載入；`catch\s*\(.*\)\s*\{\s*\}`（吞錯）；`setData\(\[\]\)` 出現在 error 分支（把失敗當空）；`new Date\(\)` 直接 format 時間而未指定時區（適用 stack：any）。
