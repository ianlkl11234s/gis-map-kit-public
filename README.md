# gis-map-kit

做網頁地圖（GIS 圖台）用的 Claude Code plugin。
plugin 是裝進 Claude Code 的擴充包；裝好後，你跟 Claude 聊地圖專案時，它會自動翻這裡的「知識卡」來回答，而不是只憑一般印象。
卡片內容來自實際做地圖的經驗：台灣開放資料 API 怎麼接、底圖怎麼選、動態效果、色票、效能、上線與踩坑。

**適合誰**：第一次做地圖網站的學生、想用台灣開放資料做專題的人、做到一半卡住想找原因的人。不需要先懂 GIS，但要會用 Claude Code。

## 安裝

### 用本機資料夾（現在可用）

把整個 gis-map-kit 資料夾放在你的電腦上，進到你自己的專案資料夾，用 `--plugin-dir` 指定 plugin 位置啟動 Claude Code：

```bash
cd <你的專案資料夾>
claude --plugin-dir <gis-map-kit 資料夾路徑>
```

每次啟動都要帶這個參數。進去後問 Claude「你有哪些 gis 開頭的 skill？」，看得到五個就代表裝好了。

### 從公開 repo 安裝

公開版在 GitHub 的 `ianlkl11234s/gis-map-kit-public`。在 Claude Code 裡加入這個 marketplace（plugin 的下載清單）再安裝，之後不用每次帶參數：

```text
/plugin marketplace add ianlkl11234s/gis-map-kit-public
/plugin install gis-map-kit@gis-map-kit
```

裝好後重新啟動 Claude Code，問「你有哪些 gis 開頭的 skill？」確認看得到五個。

## 五個 skill：什麼時候用哪個

skill 是一組寫好的工作步驟。你不用打指令，照平常講話就好，Claude 會依你說的內容自動選一個 skill 來用。

| 你說什麼 | 會用哪個 skill | 會得到什麼 |
|---|---|---|
| 「我想做某個議題的地圖，該蒐集哪些資料？」或貼一個開放資料網址 | `gis-system` | System Map（議題的關係圖）、候選資料集清單、爬取計畫，存在你專案的 `system/` 資料夾 |
| 「我想做一個地圖網站，要怎麼開始？」 | `gis-start` | 幾個關鍵問題 → 建議的技術組合（底圖、SDK、資料格式）＋第一週要做的清單 |
| 「我的圖層不顯示」「顏色要怎麼選？」 | `gis-advisor` | 最可能的原因、怎麼修、順便注意，每項附卡片編號 |
| 「幫我檢查這個地圖專案還缺什麼」 | `gis-review` | 必修／建議／可加分三級報告，附檔案與行號；只讀不改 |
| 「這堂課有 105 分鐘，我想做一個會切換兩期資料的地圖」 | `gis-workshop` | 限時課堂陪做：驗證真實資料 → 本機地圖 → 可操作的動態切換 → README 與 QA.md |

範例對話：

- gis-system：「這是 data.gov.tw 的飲用水保護區資料，想做水源污染風險的地圖，還需要哪些資料？」
- gis-start：「我想用公車資料做一個看台北哪裡最擠的地圖，該從哪開始？」
- gis-advisor：「我的人口地圖有些區是灰色，有些是最淺色，讀者分不出來哪裡沒資料，怎麼辦？」
- gis-review：「上線前幫我看看這個 MapLibre 專案有沒有要修的地方。」
- gis-workshop：「北科大 Week 09 工作坊，我想用台灣開放資料做一個可以切換時間的地圖，課堂內要完成。」

典型流程（每一步都可以單獨用，不一定要從頭走）：

```text
gis-system（先想清楚要哪些資料）
   → gis-start（選技術、做出第一版）
   → gis-advisor（做到一半遇到問題，隨時問）
   → gis-review（上線前全面檢查）

限時課堂另走一條：
gis-workshop（一堂課內：真實資料 → 本機地圖（靜態里程碑）→ 動態切換 → 驗收）
   → 課後要繼續做成長期專案，再接 gis-start
```

## 課堂工作坊怎麼用

`gis-workshop` 是給限時課堂用的：學生自由選題，在一堂課（約 105 分鐘）內做出本機可開、用真實資料的網頁地圖。**靜態版是里程碑，可以交**（真實資料＋來源授權時間、研究問題、圖例、README 與 QA.md）；**完整目標**是再加一項讓地圖內容改變的操作，動畫不是必要，切換兩期或兩個情境就夠。來不及做動態時，它會幫你先把靜態版收尾交付。公開網址是加分。

底圖預設用 OpenFreeMap 的深色樣式 dark（免 key，attribution 自動顯示；需要淺色時用 positron）；沒帶 key 的 CARTO 圖磚會整片蓋上浮水印，不要用。沒有題目時可以請它從題庫挑（入門靜態、Change、Flow、Propagation／Scenario、第一手）。

1. 在自己的空資料夾啟動 Claude Code（安裝方式見上方），第一句話講明是課堂工作坊，例如「這是 GIS 工作坊，105 分鐘內要完成」，避免被當成一般專案規劃。
2. 說出想看什麼、在哪裡，想做動態的話是哪一種變化（兩期比較、時間片段、傳遞階段、情境切換）；有資料檔或網址就一起給。
3. 照它的進度列走：選題 → 資料 → 地圖 → 動態 → 驗收。每站它會說做了什麼、怎麼驗、下一步。
4. 最後交 `README.md` 與 `QA.md`，並回答「這個結果不能說明什麼？」。QA.md 每項標 Pass／Fail／未驗證，沒在瀏覽器實際操作過的項目標「未驗證」。

資料先自己從公開來源下載。即時 API（例如 TDX 公車位置）只給「現在」，要自己隔 5–10 分鐘抓兩次快照才能比較；TDX 要先註冊會員、帳號經審核後才拿得到金鑰，請在課前辦好。自己抓不到時，用講師提供的下載連結或本機資料；再不行，它會建議縮小題目、換一種動態，或先交靜態版，不會補出假的歷史。

## 卡片怎麼讀

卡片都在 `knowledge/`，每個主題一個資料夾。總目錄是 `knowledge/INDEX.md`。

| 主題 | 內容 |
|---|---|
| 00-system-thinking | 系統思考：先想清楚議題怎麼運作，再找資料；也含視覺化即思考、Pattern→Insight |
| 01-taiwan-apis | 台灣開放資料 API 怎麼接（TDX、氣象署、環境部、水利署、data.gov.tw…） |
| 02-basemaps | 底圖怎麼選 |
| 03-dynamics | 會隨時間變的資料與時間軸 |
| 04-effects-catalog | 動態效果（軌跡、粒子、脈衝…）與靜態表現形式（點、線、面、熱區、網格、標籤） |
| 05-color | 色票與色階 |
| 06-data-formats | 資料格式與處理 |
| 07-performance | 繪製效能 |
| 08-multi-layer | 多個圖層一起開時怎麼管理 |
| 09-design-system | 設計系統（圖例、面板、字型、間距的一致規則） |
| 10-ops | 上線維運與持續收集資料 |
| 11-extras | 發布與分享（分享網址、嵌入、SEO） |
| 12-domain-pitfalls | 領域踩坑（風場、海流、航班、船舶、衛星…） |
| 13-author-taste | 作者品味（**不是業界規範**，見下方說明） |
| 14-scale-density | 尺度與密度：資料多少、縮放到哪，要用點、熱區還是網格 |
| 15-getting-started | **第一次做網頁地圖從這裡開始**：座標系統、GeoJSON、本機 server、工具鏈、最小骨架 |
| 16-spatial-analysis | 空間分析：熱點、區位商數、換尺度還成立嗎、等時圈與可達性、地理編碼 |

**怎麼找卡**：先在 `knowledge/INDEX.md` 選主題 → 打開該主題的 `_index.md`，看「什麼情況看這張」欄找到符合你狀況的卡 → 只讀需要的那幾張。每個主題的 `xx-00` 是總表（`INDEX.md` 的「總表」欄可直接點），從「遇到什麼／想做什麼」對到卡片，表裡的卡片編號都可以點進去。動態效果總表是 04-00，靜態表現形式總表是 04-20。

**每張卡六段**（00 系統思考、13 作者品味與 catalog 類總表不在此限）：

| 段落 | 寫什麼 |
|---|---|
| 原則 | 一到兩句照著做就不會踩坑的規則，先讀這段 |
| 症狀 | 你會看到什麼（畫面怪、錯誤訊息、數字不對） |
| 原因 | 為什麼會這樣 |
| 解法 | 可以照做的步驟；要取捨時列出選項與建議 |
| 怎麼偵測 | 怎麼在程式裡找出這個問題（gis-review 用它掃描） |
| 出處 | 這張卡的根據 |

**kind（卡片類型）**：pitfall＝踩坑、pattern＝做法、decision＝選型決策、catalog＝清單。

**evidence（證據等級）**：這張卡有多可靠。

| 等級 | 意思 |
|---|---|
| Evaluated | 有量測或比對結果 |
| Implemented | 有實際寫成程式 |
| Observed | 真的發生過、修過，但沒有正式量測 |
| Candidate | 研究過，還沒實作 |
| General | 一般業界建議，不是作者自己的經驗 |

**13-author-taste 是作者品味**：例如偏好深色底圖（和本工具包的預設底圖一致）、時間軸預設不自動播放。這些是作者的選擇與理由，不是對錯；你有自己的理由就照你的。資料正不正確的問題不受品味影響。

## 名詞小辭典

| 名詞 | 意思 |
|---|---|
| 圖台 | 可以開關多個圖層、看資料的網頁地圖應用 |
| System Map | 把一個議題拆成「節點」（例：降雨、排水能力、淹水）和「關係」（誰影響誰）的圖，用來決定要蒐集哪些資料 |
| 證據狀態 | System Map 裡每個節點與關係有多確定：observed（有觀測資料）、source_supported（有文件支持）、hypothesized（推測）、simulated（模擬）、unknown（不知道），避免把猜測畫成事實 |
| GeoJSON | 最常見的地理資料格式，是文字檔（JSON），好讀好改，但資料一大就慢 |
| PMTiles | 把整份地圖資料切成小塊、打包成一個檔；瀏覽器只下載看得到的那幾塊，適合大資料 |
| MVT | Mapbox Vector Tile，向量圖磚的標準格式；PMTiles 裡裝的通常就是 MVT |
| 底圖 | 地圖最下面那層（道路、地名、地形），你的資料畫在它上面 |
| attribution | 地圖角落的資料來源與版權標示；多數底圖與開放資料規定一定要顯示 |
| key／token | 使用某些服務（例如 Mapbox、TDX）的通行碼。可以公開的 token 要設網域限制；不能公開的 secret 絕對不能放進前端程式 |
| SDK | 畫地圖用的程式庫，例如 MapLibre GL、Mapbox GL、Leaflet |

## 費用與時間

用 Claude Code 會依用量計費。以下是 2026-10-30 實測（Opus 模型、各跑一次），供參考：

| 階段 | 時間 | 費用 |
|---|---|---|
| gis-system：貼網址或議題 → System Map、資料清單、爬取計畫 | 8–11 分鐘 | 約 US$5.4–5.5 |
| 確認計畫後抓免 key 資料 → gis-start 做出第一版圖台 | 約 10 分鐘 | 約 US$4.5 |
| gis-review 掃描一個小專案 | 約 3–5 分鐘 | 約 US$5.7（含 3 個子代理） |

換用較小的模型會便宜很多，但沒有實測品質；建議先用同一題比較看看。
