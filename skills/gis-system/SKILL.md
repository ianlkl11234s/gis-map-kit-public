# gis-system：先建立系統，再找資料，再做圖台

知識庫在本 plugin 根目錄的 `knowledge/`（本檔往上兩層）。方法卡在 `knowledge/00-system-thinking/`，先讀它的 `_index.md`。

**核心原則：不問「還能加什麼圖層」，問「這個系統怎麼運作」。** 圖層集合不等於系統理解（00-01）。

## 產出（寫到使用者專案的 `system/` 資料夾，沒有專案就問要放哪）

| 檔案 | 內容 |
|---|---|
| `system.json` | System Map，格式照 00-09（System／Node／Edge／Source／Dataset），欄位名不可自創 |
| `system.md` | 給人看的版本：中心問題、邊界、六層表、每條邊一句話、關鍵不確定性 |
| `datasets.md` | 候選資料集清單，每筆附驗證狀態 |
| `crawl-plan.md` | 爬取計畫（步驟 6），使用者確認前不執行 |

## 步驟

### 0. 確認入口與目的（最多 3 題，已知的跳過）
- **入口**：貼網址＝data-first；給議題＝question-first（00-08）。兩者最後都要回到同一個迴圈。
- **目的**：探索／教學／實際決策？決定邊界嚴格程度（00-07）。
- **範圍**：地理範圍與時間範圍。
- 使用者沒有回應（或說不用問）時：每個選擇都採你最推薦的選項，並在 `system.md` 開頭的「假設」段寫明選了什麼、為什麼。

### 1. 讀懂起點資料（data-first 才需要）
- data.gov.tw 網址：`python3 <本 skill>/scripts/datagov.py meta <網址或 ID>`，讀標題、說明、欄位、格式、更新頻率、授權、下載方式。
- 其他平台：用 WebFetch 讀頁面；讀不到（需要 JS）就照實說，改用 WebSearch。
- 判斷這份資料在系統裡扮演什麼：條件？觸發？狀態？暴露？影響？介入？它是**觀測、申報、推估還是模擬**？

### 2. 找出中心現象，長出系統
讀 00-01 到 00-06。
- 從資料或議題反推它描述的**現象**；一份資料可能屬於多個系統，列出 2–3 個候選系統讓使用者挑一個（AskUserQuestion）。
- 用六層模板展開（00-04）：Baseline／Susceptibility → Trigger／Hazard → System State → Exposure／Vulnerability → Impact／Cascading → Intervention／Scenario，再看有沒有回饋。這是教學框架，不是官方標準，對使用者也這樣說。
- 每個節點寫 type 與定義。**節點的定義只能包含有資料或來源支持的部分**：例如有集水區範圍、沒有河網流向，就拆成「集水區範圍」（observed）與「上下游連通」（unknown），不要合成一個 observed 節點。用代理資料表示的節點（例：沒有取水口點位，用法定範圍面代替）設 `is_proxy: true`，不可標 observed。
- 每條邊寫 relationship_type、verb_label、directed、evidence_status、confidence_basis（00-03、00-05）。
- 動態特徵：標出 Stock、Flow、Trigger、Delay、Threshold（00-06），這會決定之後圖台要不要做時間軸、做哪種動態。

### 3. 自我檢查（照 00-09 的清單，不通過就改）
- **先跑硬性檢查**：`python3 <本 skill>/scripts/check_system.py <system 資料夾>`，有 ERROR 就修到 0 才往下（步驟 5 補完資料集後再跑一次）。
- 每條邊都有動詞與證據狀態；沒有來源的只能是 hypothesized 或 unknown。
- 共現／鄰近（association）沒有被寫成因果；「附近有工廠」不等於「造成污染」（00-08）。
- 有沒有孤立節點、說不出理由的邊、跟中心問題無關的節點。
- 影響大但沒資料的因素列為 critical_uncertainties，不默默刪掉（00-07）。

### 4. 每個節點長出問題 → 證據 → 指標 → 資料（00-08、00-10）
對每個關鍵節點與邊，寫「要驗證什麼」「什麼事實能支持或否定」「怎麼量」「可能需要哪類資料」。

### 5. 找候選資料集（地毯式搜尋，但每筆都要驗證）

**5a. 先建涵蓋矩陣**：列 =「步驟 4 的每個資料需求」，欄 = 六層、資料型態（點／線／面／行政區統計／時序）、可能的主管機關。每一格都要有搜尋紀錄（用了哪些關鍵字、在哪裡找、結果），找不到也要記「找不到」。矩陣寫在 `datasets.md` 開頭。

**5b. 系統性的找法**（依序做，每種都要做過）：
1. data.gov.tw 全文搜尋：`python3 <本 skill>/scripts/datagov.py search <關鍵字>`。關鍵字來自：資料需求的同義詞、機關名、法規名、流域或地名。
   - 關鍵字一次只放一個短詞，寫「找不到」前至少用 2 個單詞同義詞搜過（見 01-05）。
2. 從已驗證的資料反查：它的 tags、提供機關、related_url、說明裡提到的法規，各再搜一輪（同一機關常有成套資料）。
3. 主管機關自己的平台：對照 `knowledge/01-taiwan-apis/01-00` 平台總覽（氣象署、TDX、水利署、環境部、國土測繪等），用 WebSearch `site:<機關網域> <關鍵字>` 找，不要憑記憶寫網址。
4. 地方政府平台：範圍是某縣市時，查該縣市的開放資料平台（例：data.taipei），用 WebSearch 找入口後再搜。
5. 地圖服務：有 WMS／WMTS 的機關，讀 GetCapabilities 看有哪些圖層（可直接疊加，不一定要下載）。

**停止條件**：矩陣每一格都有紀錄，且連續兩輪新關鍵字沒有找到新的可用資料集；或搜尋呼叫達 40 次。到上限時在 `datasets.md` 寫明還沒搜過的格子。

**5c. 驗證等級**（每筆資料集都要標 `verification_level`，寫進 system.json 的 Dataset）：
| 等級 | 意思 | 怎麼達到 |
|---|---|---|
| `title` | 只看過標題或搜尋結果 | — |
| `metadata` | 讀過 metadata：機關、格式、欄位、更新頻率、授權、下載方式 | `datagov.py meta` 或 WebFetch 官方頁面 |
| `sample` | 實際抓過幾筆，確認欄位與座標真的有值 | 抓 ≤200 筆或一個小檔 |
| `fit` | 確認能算出步驟 4 的某個指標（例：有座標、時間解析度夠） | 看過樣本後寫明能算哪個指標、限制是什麼 |

另外記錄每筆的：空間單位（點／線／面／行政區）、時間解析度、是觀測／申報／推估／模擬、要不要 key。
- 節點或邊要標 observed／source_supported，連到的資料集至少要 `metadata`；只到 `title` 的資料集不能撐起證據。
- **找不到就寫找不到**，不可補一個看起來像真的資料集或網址。
- 名稱相近但法律基礎或定義不同的資料要分開並說明差異（例如不同機關公告的「保護區」），不可合併成一筆。
- 寫回 `system.json` 的 Dataset，並在節點與邊的 dataset_ids 連過去；做一張「資料覆蓋表」：哪些節點與邊有資料、哪些只能用 proxy、哪些完全沒有。完成後再跑一次 `check_system.py`。

### 6. 爬取計畫（地毯式抓資料的計畫，不是直接開抓）
`crawl-plan.md` 每筆寫：資料集、取得方式（檔案下載／API 分頁／需登入）、要不要 key、格式、預估筆數或大小、更新頻率（一次性／定期／即時）、授權與標示方式、優先序（P1＝中心問題必要、P2＝驗證關鍵邊、P3＝延伸）。
- P1、P2 只能放 verification_level 至少 `metadata` 的資料集；只看過標題的一律放「待驗證」段，不排優先序。
- 需要 key、需要登入、或條款不允許自動抓取的，只列出不抓，註明使用者要自己申請。
- 即時資料要寫成「持續收集」，並引用 `10-ops` 的監控與告警卡；一次性抓取不等於收集管線。
- 預設限速：同一網域每秒最多 1 次請求；測試時每份資料先抓幾百筆看格式，不整包下載。
- 計畫檔開頭寫 `狀態：waiting_confirmation`。**停下來請使用者確認計畫**，確認後才執行（執行後把狀態改成 `executed <日期>：<範圍>`）；執行時把原始檔與抓取時間、來源網址存在一起（之後圖台的 popup 要顯示來源與資料時間）。

### 7. 交接給圖台
告訴使用者：系統與資料清單已就緒，接著用 gis-start 選技術組合。交接時帶上：
- 系統的動態特徵（決定時間軸與動態效果，見 03、04）
- 各資料的空間單位與格式（決定圖層類型與資料格式，見 06）
- 每層要標的證據狀態（觀測／推估／模擬要在圖例與 popup 分開標示，見 06-08、09-04）

## 原則
- 不假造：來源、資料集、欄位、網址都要實際讀到；推論要標 hypothesized。
- 資料還不是證據：疊在同一張地圖上不代表有關係，圖台的說明文字也不能把「附近」講成「影響」。
- 本 skill 只查公開 metadata 與少量樣本，不申請帳號或 key，不大量下載，不打需付費的 API。
- 沒有使用者的私人資料目錄時，候選資料集的廣度受限於 data.gov.tw 搜尋與網路搜尋；照實告訴使用者還有哪些平台沒涵蓋。
