# 學生交付樣板：README 與 QA.md

## 專案結構（已有專案可依原結構調整）

```text
student-project/
  README.md      問題、怎麼啟動、怎麼操作動態、資料來源與時間、限制
  QA.md          測過什麼、沒測什麼、各項 Pass／Fail／待人工驗證
  index.html     或 src/：地圖程式
  data/          小型已驗證快照；不能轉發的資料只寫取得方式
```

原始大檔、key、`.env` 不放進要公開的資料夾（10-01、10-04）。

## QA.md 樣板

每項填 Pass／Fail／待人工驗證，並寫證據（截圖檔名、觀察到什麼、執行的指令）。只看程式碼推測的，標「推測」。

```markdown
| 項目 | 結果 | 證據 |
|---|---|---|
| 本機啟動並在瀏覽器開啟（沒有瀏覽器工具就寫待人工驗證） | | |
| 有真實資料，來源、授權、資料時間都寫在 README 與畫面上 | | |
| 座標落在正確位置；換過座標系有記錄 | | |
| 動態：至少兩個狀態可切換，地圖內容確實改變 | | |
| 動態路徑規則：Change 口徑一致／Flow 不外推不跨斷訊／Scenario 有參數說明／Propagation 有機制或假設 | | |
| 缺值、無資料、載入失敗有畫面提示；缺值不畫成 0 | | |
| 圖例顏色與地圖一致；底圖 attribution 看得到 | | |
| 照 README 能重現啟動與動態操作 | | |
| synthetic-demo 資料有標示，且沒有算進真實資料 | | |
```

## agent 自己驗收時

- 有瀏覽器工具就實際打開、切換每個狀態、截圖，並看 console 有沒有錯誤。
- 沒有瀏覽器工具就把「瀏覽器」相關項目全標待人工驗證，告訴學生要親手點哪幾下、應該看到什麼。
- 程式能跑、測試通過，都不能代替畫面實測。
