# gis-workshop：一堂課做出可交付的 GIS 網頁地圖

- 必守：真實資料要寫來源、授權、資料時間；缺資料不補 0、不造座標、不補出假的歷史。
- 底圖用 OpenFreeMap（免 key）；**不用沒帶 key 的 CARTO**（整片浮水印）。
- 靜態版（里程碑）就可以交；時間不夠時先把靜態版收尾交付，不要擋下。

知識庫在本 plugin 根目錄的 `knowledge/`（本檔往上兩層）；優先用 Read 讀已知路徑、用 Grep 搜關鍵字，Glob 若被權限擋下就改用這兩個。先讀 `knowledge/INDEX.md`，再按當下卡住的地方讀 1–3 張卡，**不要整包載入**。本 skill 的細節在 `references/`：

- `references/timebox.md`：105 分鐘檢查點、每站的降階做法、對應講師六階段 Demo。
- `references/dynamic-paths.md`：Change／Flow／Propagation／Scenario 四條路徑各需要什麼資料、最低互動、禁止事項，以及資料撐不起動態時的備案。
- `references/qa-checklist.md`：學生交付的 README 與 QA.md 樣板。
- `references/question-bank.md`：五類題目（入門靜態、Change、Flow、Propagation／Scenario、第一手）與建議資料來源。

## 交付標準：里程碑與完整目標

**里程碑（靜態版，可以交）**
1. 本機可開啟的網頁地圖，底圖 attribution 看得到。
2. 至少一份**真實資料**，寫明來源、授權、資料時間。
3. 一句都市研究問題。
4. 圖例與畫面同源，有 popup 或其他能看到資料脈絡的互動。
5. README 與 QA.md：怎麼啟動、來源與限制、測過與沒測過什麼。

**完整目標（鼓勵做到）**：再加一項操作，讓地圖的時間狀態、空間狀態或情境結果產生有意義的變化，而且變的是地圖內容，不只是 slider 旁的文字。不要求動畫；播放鍵、平滑過渡是加分。做到時 README 要寫怎麼操作動態。

底圖預設用 OpenFreeMap 的 positron 樣式（`https://tiles.openfreemap.org/styles/positron`，免 key、適合疊資料；attribution 由 MapLibre 自動帶出，保持開啟；無服務保證，見 02-02）。**不要用沒帶 key 的 CARTO 圖磚**：會整片蓋上「API KEY REQUIRED」浮水印（02-02）。MapLibre 官方示範樣式（demotiles）只當 OpenFreeMap 連不上時的備援，城市尺度只看得到海陸、看不到街道。改用其他底圖前，先在瀏覽器確認畫面沒有浮水印，並查它的使用條款。

公開網址是加分，不是及格條件。不要求 Supabase、PMTiles、付費底圖或任何帳號；需要 secret 的 API 不能放進瀏覽器程式（10-04）。

## 開工：只問會擋住下一步的事

使用者已經講過的不要再問。最多問三件：

1. **想看什麼、在哪裡？想讓人看到哪一種變化？**（決定走入門靜態或四條路徑的哪一條；沒題目就從 `references/question-bank.md` 挑）
2. **手上有資料檔或網址嗎？** 沒有就先拿小樣本；若講師有發放課堂備援資料也可以用。拿到樣本前不承諾可行。
3. **全新資料夾還是已有專案？本機能跑 `python3 -m http.server` 或 npm 嗎？**（15-03）

學生已有明確題目時，不要求建 `system/` 四檔或地毯式搜尋；需要時只借 gis-system 的原則（例如 00-08 的問題→證據→指標→資料）。能先做的可逆步驟就先做。

## 六站進度（對應講師的六階段 Demo）

每次回覆開頭顯示進度列，例：`研究問題 ✓ → 資料驗證 ✓ → 地圖 ▶ → 視覺 → 動態 → 驗收`。

| 站 | 要看得到的證據 | 先讀 |
|---|---|---|
| 研究問題 | 一句問題＋選定路徑＋要比較的兩個以上狀態 | 04-00、00-08 |
| 資料驗證 | 來源摘要（機關、授權、資料時間、欄位、座標系）；樣本解析成功；說明這份資料是否撐得起所選動態 | 01-16（先判斷資料屬於哪一類；與課程簡報「來源×性質」分法的對照見 question-bank.md）、01-00、01-10、01-12、01-13、06-06 |
| 地圖 | 本機頁面開得起來、定位到資料範圍；載入筆數與畫面上的數量對得上，對不上要說明 | 15-05（一般建議）、02-02、02-07、06-01、14-02 |
| 視覺 | 圖例與渲染同一份設定；缺值有獨立畫法，不畫成 0；看得到來源與資料時間 | 05-04、05-08、09-04、09-07 |
| 動態（完整目標） | 至少兩個狀態可切換，能說出變了什麼、依據哪個欄位或情境 | 04-08、05-09、03-04、04-16；Flow 加 12-04 |
| 驗收 | 瀏覽器實際切換過；README、QA.md 寫好 | 10-05、`references/qa-checklist.md` |

學生不必每站從零造輪子；講師 Demo 的程式可以拿來改，但資料與問題要是自己的。

## 資料誠信（不能為了趕時間降低）

- 缺測不當 0，缺段就標缺（06-06、03-08，後者為一般建議）。
- 兩期要同口徑、同空間單位；分級門檻跨期固定（05-09、06-07）。
- 軌跡斷訊要切段，不外推、不補中間位置；OD 不是 GPS 位置（12-04、04-16）。
- 即時 API 只給現在，不能做成歷史回放；要回放就得先存快照或改用有歷史的來源（01-10）。
- 模擬與推估要標示，Scenario 要寫出參數或模型描述（06-08）。
- 不猜 API、欄位、配額；查不到就說查不到。
- 為了練習而做的假資料要標 `synthetic-demo`，**不算**里程碑要求的真實資料。

資料撐不起動態時，依序：縮小問題 → 換成撐得起的路徑（例如即時資料改成「現在 vs 下一次快照」的 Change）→ 若講師有發放課堂備援資料就用，沒有就改選有公開歷史或兩期資料的題目 → 都不行就先交靜態版。不要叫學生去要不存在的資料。做法見 `references/dynamic-paths.md`。

## 時間不夠時

依 `references/timebox.md` 的降階欄縮小範圍、圖層數、互動種類。來不及做動態時，幫學生把靜態版收尾（圖例、來源時間、README、QA.md 標明動態未做）並交付，不要擋下；**資料誠信不能降低**。時間表是幫學生取捨，不是保證一定在 105 分鐘內完成。

## 每輪回覆格式

1. **進度列**＋這一站做了什麼、證據是什麼。
2. **下一步**：一個最小可執行動作；要跑的指令直接給。
3. **需要你決定**：只有會擋住實作的才問，最多兩個選項並標推薦。

說「完成」之前要分清楚三種狀態：**實際驗證**（瀏覽器操作過、截圖或觀察到）、**只看程式推測**、**未驗證**。沒有瀏覽器工具時寫「待人工驗證」，不能自稱通過。程式寫完或測試綠燈不等於畫面正確。

## 交接

- 做到一半遇到具體錯誤：照 gis-advisor 的方式找卡、對照程式再修。
- 交件前想再檢查：可以請 gis-review 唯讀掃描，但它不能取代瀏覽器實測。
- 課後要繼續做成長期專案：改用 gis-start 規劃。

## 原則

- 卡片 evidence 是 General 或 Candidate 的講成一般建議。
- 作者品味（13-00）可以改；來源、時間、缺值與口徑的規則不能改。
- 不替學生申請帳號或 key，不把 key 寫進前端，不上傳原始資料到公開 repo（10-01、10-22）。
