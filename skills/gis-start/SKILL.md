# gis-start：GIS 圖台起步引導

## 必守規則
1. 預設底圖照 `knowledge/DEFAULTS.md`：OpenFreeMap dark 樣式（`https://tiles.openfreemap.org/styles/dark`，免 key；需要淺色用 positron）；給範例程式時 `style` 一律寫 dark 的網址，使用者明確要淺色才換 positron，要顯示 attribution（02-07）；不用沒帶 key 的 CARTO 圖磚（整片浮水印，02-02）。
2. 用真實資料就在 popup 或頁尾寫來源、授權、資料時間。
3. 缺資料不補 0、不造座標；缺值要畫成看得出來的「無資料」（05-04）。
4. 每項建議附卡片編號；General／Candidate 的卡講成「一般建議」。
5. 不替使用者申請帳號或 key，也不把 key 寫進前端程式碼（01-08）。

知識庫在本 plugin 根目錄的 `knowledge/`（本檔往上兩層）；優先用 Read 讀已知路徑、用 Grep 搜關鍵字，Glob 若被權限擋下就改用這兩個。先讀 `knowledge/INDEX.md`（主題總覽），再讀該主題的 `_index.md` 找卡片，**只讀需要的卡**，不要整包載入。

## 步驟 0：先有系統，再選技術

- 使用者只給了一個議題或一個開放資料網址、還不清楚要哪些資料 → 先走 **gis-system**（建立 System Map、候選資料集、爬取計畫），完成後再回來。
- 專案裡已經有 `system/system.json` → 先讀它：動態特徵決定要不要時間軸，資料的空間單位與格式決定圖層與格式，證據狀態決定圖例怎麼標。步驟 1 已能從中得到答案的題目就不再問。
- 使用者已經清楚要哪幾份資料 → 直接進步驟 1。

## 步驟 1：問清楚（一次問完，最多 5 題）

用 AskUserQuestion（沒有就用條列）問，使用者已經講過的跳過：

1. **資料是什麼、多新？** 靜態（一次下載）／定期更新（每天、每月）／即時（每分鐘）→ 決定資料管線與格式。
2. **要表達什麼？** 分布（哪裡多）／比較（A vs B）／變化（隨時間）／流動（從哪到哪）／事件（何時何地發生）→ 決定圖層類型與要不要動態。
3. **誰用、用什麼裝置？** 自己研究／課堂展示／公開網站；手機為主還是電腦 → 決定 RWD 與效能預算。
4. **預算與帳號？** 能不能用要付費或要 key 的服務（Mapbox、Google）→ 決定底圖。
5. **規模？** 大約多少點／面、範圍是一個區、一個縣市還是全台 → 決定 GeoJSON 還是 PMTiles／後端。

## 步驟 2：建議技術組合

使用者是第一次做網頁地圖（不熟座標、GeoJSON、本機 server）時，先讓他讀 `15-getting-started`，MVP 從 15-05 最小骨架開始。分析型需求（熱點、可達性、地理編碼）看 `16-spatial-analysis`。

依答案讀這些卡再給建議，每一項附一句理由與卡片 id：

| 決定 | 先讀 |
|---|---|
| 底圖與渲染 SDK | `02-basemaps` 的 02-01、02-02 |
| 資料來源怎麼接 | `01-taiwan-apis` 的 01-00，再看對應平台卡 |
| 資料格式 | `06-data-formats` 的 06-01；量大或要即時看 `07-performance` 的 07-02、07-07 |
| 要不要動態、用哪種 | `04-effects-catalog` 的 04-00、04-01、04-16（不假造動態）；時間軸看 `03-dynamics` 的 03-01 |
| 色階 | `05-color` 的 05-01 |
| 資料量與縮放（直接畫點、熱區、網格、圖磚，何時切換） | `14-scale-density` 的 14-00 總表 |

使用者沒特別需求時，SDK 用 MapLibre、底圖用 OpenFreeMap dark（必守規則 1）；使用者問到設計風格再參考作者品味 13-00 總表，並說明這是作者偏好。資料格式先用 GeoJSON（大到載入變慢再轉 PMTiles，判斷方式見 06-01）、先做靜態版再加動態。若使用者要用的是不熟悉的領域資料（風場、海流、航班、船舶、衛星），一定先讀 `12-domain-pitfalls` 的 12-00。

## 步驟 3：第一週 MVP 清單

產出可勾選的清單，每項標「必做／建議／之後」：

- 必做：一張地圖＋一個資料圖層、圖例、點擊 popup（含資料來源與資料時間）、loading 與錯誤狀態、缺值不畫成 0（見 05-04、09-07）、底圖 attribution（02-07）。
- 必做（實測常漏，細節在卡片）：
  - 面與線先簡化，單層檔案大小門檻見 06-05。
  - 地圖 `load` 前停用圖層開關、讀開關實際狀態：08-03。
  - 錯誤訊息寫給使用者、可關、成功後清掉：09-07。
  - 決定發布範圍（原始資料、腳本、`system/` 不上傳）：10-01。
  - 關鍵說明要看得見，不只放 hover title：09-09。
- 建議：透明度控制、手機版面最低清單（09-09）、分享網址記住畫面（08-08）。
- 之後：動態效果、多圖層、SEO 與嵌入（11-extras）、部署與持續更新（10-ops 的 10-00 總表）。

## 步驟 4：交接

最後告訴使用者：做到一半有問題可以直接描述症狀（會用 gis-advisor），做完一輪可以說「幫我檢查還缺什麼」（會用 gis-review）。

## 原則

- 卡內標「待官方驗證」的配額、價格、授權，要提醒使用者自己查官方頁面，不要報數字當定論。
