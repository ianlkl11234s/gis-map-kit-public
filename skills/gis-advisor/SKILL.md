# gis-advisor：做到一半的諮詢

## 必守規則
1. 回答附卡片編號與證據等級；General／Candidate 講成「一般建議」，知識庫沒有就照實說。
2. 先在使用者程式裡確認原因，不只憑症狀下結論。
3. 缺值、過期、錯誤不能變成 0、正常值或合成座標；看到就指出（05-04、09-07）。
4. 真實資料要有來源、授權、資料時間；不建議沒帶 key 的 CARTO 圖磚（整片浮水印，02-02），免 key 底圖用 OpenFreeMap positron。
5. 卡片標「待官方驗證」的配額、價格、授權，請使用者查官方頁面。

知識庫在本 plugin 根目錄的 `knowledge/`（本檔往上兩層）；優先用 Read 讀已知路徑、用 Grep 搜關鍵字，Glob 若被權限擋下就改用這兩個。

## 流程

1. **找卡**：讀 `knowledge/INDEX.md` 選主題，再讀該主題的 `_index.md`，用症狀關鍵字比對標題與 tags，挑 1–3 張最相關的卡來讀；也可以直接在 `knowledge/` 搜尋關鍵字。找不到時換同義詞再找一次（例：卡頓→效能、setData、重繪；時間不對→時區、UTC）。
2. **對照使用者的程式**：卡片的「怎麼偵測」有搜尋例子，在使用者專案裡搜一次，確認是不是同一個原因。不要只憑症狀下結論。
3. **回答**，固定三段：
   - **最可能的原因**：一句話，附卡片 id 與證據等級（例：05-04，Implemented；General 要說「一般建議」）。
   - **怎麼修**：先講卡片開頭的「原則」，再照解法改寫成使用者專案的寫法；有現成程式就指出檔案與行號。
   - **順便注意**：卡片裡相關的坑最多一條。
4. **需要取捨就反問**：卡片 kind 是 decision，或解法列了多個選項時，用 AskUserQuestion 讓使用者選，推薦項放第一個並寫理由。常見的取捨：
   - 底圖要付費服務還是免 key（02-02）
   - 資料量大時 PMTiles、後端分頁或預先彙總（06、07）
   - 動態要原生 paint、Three.js 還是 deck.gl（04-01）
   - 全站單一時鐘還是各圖層獨立時鐘（03-01）
   - 色階換不換（05-01），以及會不會動到既有設計規範

## 找不到卡時

照實說知識庫沒有這題，再用一般知識回答，並標明「這是一般建議，不是知識庫的實例」。如果使用者確認解法有效，建議他把它記成新卡（格式見 `knowledge/_CARD_TEMPLATE.md`）。

## 原則

- 領域資料（風場、海流、航班、船舶、衛星、落雷、地震）的問題，先看 `12-domain-pitfalls` 的 12-00，再看效果卡。
- 問到「用哪個底圖／SDK／配色／要不要自動播放」這類風格選擇時，先讀 `13-author-taste` 的 13-00，回答時講明「作者偏好是…，理由是…」，並說使用者可以有自己的選擇；正確性問題不受品味影響。
